# Painel editorial, blog e Firebase

- O painel está em `src/app/admin/` e `src/components/admin/`. `src/proxy.ts` redireciona pela presença de cookie para UX; a autorização real das páginas está em `src/app/admin/(painel)/layout.tsx` via `requireEditor()`. APIs que leem ou alteram dados protegidos validam sessão com `requireEditorApi()`; a rota de saída do preview apenas desativa o próprio `draftMode`.
- `src/lib/auth/session.ts` verifica cookie Firebase, revogação e claim `editor`; `session-constants.ts` contém constantes puras importadas pelo proxy Edge. A API de sessão em `src/app/api/admin/session/route.ts` cria e revoga cookies. Mutação administrativa também confere origem com `src/lib/http/origin.ts`.
- `src/lib/blog/types.ts` define schemas Zod de post/bloco; `queries.ts` lê; `mutations.ts` escreve; `schema.ts` valida documentos persistidos; `serialize.ts` converte timestamps. `revalidate.ts` atualiza listagem, detalhe, slug antigo e sitemap após publicação, despublicação, exclusão ou edição de post publicado.
- O preview em `src/app/api/admin/preview/` usa `draftMode`; o detalhe público só busca rascunho nesse modo. Posts publicados são consultados por slug com fallback para `legacyId`; preserve URLs legadas ao mexer na resolução.
- Uploads usam signed URL emitida por `src/app/api/admin/uploads/route.ts`; o browser envia diretamente ao bucket. O schema de post restringe novas URLs de imagem ao bucket configurado. Confira os headers assinados em `src/components/admin/image-upload-field.tsx` e `firebase/cors.json` se alterar o fluxo.
- O app usa `src/lib/firebase/admin.ts` no servidor; scripts Node usam `admin-core.ts` diretamente. `src/lib/firebase/client.ts` carrega apenas Auth no login. `firebase/firestore.rules` e `firebase/storage.rules` negam acesso direto do SDK client; Admin SDK e signed URLs seguem outras credenciais/permissões.
- Credenciais possíveis do Admin SDK: service account em base64, ADC local ou Workload Identity Federation na Vercel, conforme `src/lib/firebase/admin-core.ts`. Consulte `.env.example`, `Dockerfile` e `CLAUDE.md` antes de mudar variáveis ou deploy. Não leia valores de `.env.local`.

Confirme o comportamento em cada arquivo antes de editar. Operações como `pnpm blog:migrar`, `pnpm editor:criar`, `pnpm editor:revogar` e `pnpm firebase:deploy-rules` alteram sistemas externos; não as execute como verificação de uma mudança de código.
